# Support

## Before you ask

The [README](README.md) covers installation, options, outputs and the security model. `/vuln-hunt:options`
lists every option with its values and default, and `/vuln-hunt:scan help` shows the argument forms.

## Where to ask

| Question | Where |
|---|---|
| How to install, configure or run vuln-hunt | [Question form](https://github.com/developingchet/vuln-hunt/issues/new?template=question.yml) |
| A reproducible problem in vuln-hunt | [Bug report form](https://github.com/developingchet/vuln-hunt/issues/new?template=bug_report.yml) |
| A new option, stage or check | [Feature request form](https://github.com/developingchet/vuln-hunt/issues/new?template=feature_request.yml) |
| A vulnerability in vuln-hunt | [Private vulnerability reporting](https://github.com/developingchet/vuln-hunt/security/advisories/new), as [SECURITY.md](SECURITY.md) describes. Never a public issue. |
| Claude Code, its workflow runtime or the models | [Claude Code issues](https://github.com/anthropics/claude-code/issues) at Anthropic |
| A conduct concern | [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md), through its private reporting channel |

## What not to post

Attestations, results and reports describe the repository that was scanned. Before pasting them, remove file
names, code and findings from any repository you may not share, and never post an unfixed vulnerability in
someone else's repository. Reproduce problems on a small public or throwaway repository when you can.

Only the latest release and the latest commit on `main` receive fixes; see
[Supported versions](SECURITY.md#supported-versions).
